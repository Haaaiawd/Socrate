# Contract: `/teacherkit.prepare` Command

**Command**: `/teacherkit.prepare`  
**Phase**: 2 - Knowledge Point Preparation  
**Status**: Required  
**Purpose**: Extract detailed knowledge point content and formulate Socratic questions for teaching dialogue

---

## 职责边界 (Responsibility Boundaries)

### 本命令负责 (This Command Handles)

1. **知识点详细展开** (Knowledge Point Elaboration)
   - 读取 `/teacherkit.outline` 生成的大纲文件
   - 为每个知识点补充详细内容(定义、原理、示例)
   - 准备教学对话所需的完整知识库

2. **苏格拉底问题设计** (Socratic Question Design)
   - 为每个知识点设计引导性问题
   - 问题遵循由浅入深的层次结构
   - 问题类型: 概念理解 → 原理探究 → 应用场景

3. **教学策略细化** (Teaching Strategy Refinement)
   - 基于大纲的教学计划,细化每个知识点的教学方法
   - 准备类比、案例、对比等教学素材
   - 标记关键检查点的具体问题

4. **输出文件生成** (Output File Generation)
   - 生成 `data/chapters/[name]-prepared.md`
   - 包含所有知识点的详细内容和苏格拉底问题
   - 为 `/teacherkit.lesson` 提供完整的教学剧本

### 本命令不负责 (Out of Scope)

- ❌ 生成学习大纲(已由 `/teacherkit.outline` 完成)
- ❌ 开始教学对话(交由 `/teacherkit.lesson`)
- ❌ 生成实操练习代码(交由 `/teacherkit.practice`)
- ❌ 质量检查(交由可选的 `/teacherkit.check`)

---

## 输入约定 (Input Contract)

### 前置条件 (Prerequisites)

**必须**: 已执行 `/teacherkit.outline` 并生成大纲文件

**触发**: 用户输入 `/teacherkit.prepare`

**自动读取**:
- `data/outlines/[latest]-outline.md` (最近生成的大纲文件)
- 或用户指定: `/teacherkit.prepare data/outlines/python-loops-outline.md`

### 输入验证 (Input Validation)

| 场景 | 验证规则 | 失败处理 |
|------|---------|---------|
| 无大纲文件 | 检查 `data/outlines/` 是否有文件 | 提示: "请先执行 `/teacherkit.outline` 生成大纲" |
| 大纲文件损坏 | 验证YAML frontmatter和Markdown结构 | 提示: "大纲文件格式错误,请重新生成" |
| 知识点过多 | 检查知识点数量(>50个) | 警告: "知识点较多,准备时间较长(约X分钟)" |

## 处理流程 (Processing Flow)

### 阶段1: 大纲解析 (Outline Parsing)

**步骤**:
1. 读取大纲文件的YAML frontmatter(元数据)
2. 解析知识结构部分(章节 → 主题 → 概念)
3. 读取教学计划(时间分配、引入策略)
4. 提取所有知识点的ID、名称、学习目标

**输出**: 知识点列表(待补充详细内容)

### 阶段2: 知识点内容准备 (Content Preparation)

**对每个知识点,准备以下内容**:

#### 2.1 核心定义 (Core Definition)
- **What**: 用1-2句话清晰定义概念
- **Why**: 为什么这个概念重要/有用
- **Where**: 在什么场景下使用

**示例**:
```markdown
### 概念: Python for循环

**定义**: for循环是一种迭代结构,用于遍历序列(列表、字符串、range等)中的每个元素并执行操作。

**重要性**: 自动化重复操作,避免手动编写大量重复代码,是数据处理和批量操作的基础工具。

**应用场景**: 处理列表数据、批量文件操作、数据清洗、统计计算等。
```

#### 2.2 原理解释 (Principle Explanation)
- **How it works**: 内部运行机制(可简化,不过度技术化)
- **关键要素**: 组成部分(如for循环的"迭代变量"、"可迭代对象"、"循环体")
- **执行流程**: 步骤化说明(1→2→3)

**示例**:
```markdown
**原理**:
1. Python从可迭代对象中取出第一个元素
2. 将元素赋值给迭代变量
3. 执行循环体代码
4. 返回步骤1,取下一个元素,直到遍历完所有元素

**关键要素**:
- **迭代变量**: 如 `for item in ...` 中的 `item`
- **可迭代对象**: 如列表 `[1, 2, 3]`
- **循环体**: 缩进的代码块
```

#### 2.3 代码示例 (Code Examples)
- **简单示例**: 最基础的用法(3-5行代码)
- **实用示例**: 真实场景应用(10-15行)
- **对比示例**: 与其他方法对比(如for vs while)

**示例**:
```markdown
**简单示例**:
\`\`\`python
for i in range(5):
    print(i)  # 输出 0 1 2 3 4
\`\`\`

**实用示例**:
\`\`\`python
# 计算列表中所有偶数的和
numbers = [1, 2, 3, 4, 5, 6]
even_sum = 0
for num in numbers:
    if num % 2 == 0:
        even_sum += num
print(even_sum)  # 输出 12
\`\`\`
```

#### 2.4 常见陷阱 (Common Pitfalls)
- 新手容易犯的错误
- 概念混淆点
- 注意事项

**示例**:
```markdown
**常见错误**:
- ❌ 忘记缩进循环体
- ❌ 在循环中修改正在遍历的列表
- ❌ 混淆 `range(5)` 和 `range(1, 6)`
```

### 阶段3: 苏格拉底问题设计 (Socratic Questions)

**问题层次结构** (3层渐进):

#### 层次1: 概念理解问题 (Conceptual Understanding)
- 检验学生是否理解基本定义
- 识别概念与其他概念的区别
- 激活已有知识

**示例问题**:
```markdown
**问题1**: 你能用自己的话解释什么是for循环吗?
**预期回答**: [学生用自己的语言描述]
**检查点**: 是否提到"遍历"、"重复操作"关键词

**问题2**: for循环和while循环有什么不同?在什么情况下你会选择for而不是while?
**预期回答**: [对比两者,提到"已知次数"vs"条件控制"]
**检查点**: 是否理解for适用于已知范围的迭代
```

#### 层次2: 原理探究问题 (Principle Exploration)
- 引导学生思考内部机制
- 预测行为和结果
- 理解参数影响

**示例问题**:
```markdown
**问题3**: 如果我们写 `for i in range(3)`,循环会执行几次?i的值会是什么?
**预期回答**: [3次,i的值是0, 1, 2]
**检查点**: 是否理解range从0开始且不包含结束值

**问题4**: 观察这段代码:
\`\`\`python
for i in [10, 20, 30]:
    print(i * 2)
\`\`\`
不运行代码,你能预测输出吗?为什么?
**预期回答**: [20, 40, 60,因为每个元素都乘以2]
**检查点**: 是否能追踪循环执行过程
```

#### 层次3: 应用场景问题 (Application Scenarios)
- 引导学生将概念应用到实际问题
- 设计问题解决方案
- 选择合适的工具

**示例问题**:
```markdown
**问题5**: 假设你有一个学生成绩列表 `[85, 92, 78, 90, 88]`,你想找出所有90分以上的成绩。你会如何用for循环实现?
**预期回答**: [学生尝试设计代码逻辑]
**检查点**: 是否能组合for循环+条件判断

**问题6**: 在什么情况下,你会选择不使用for循环,而使用列表推导式?
**预期回答**: [简单的转换操作、代码更简洁]
**检查点**: 是否理解不同工具的适用场景
```

### 阶段4: 教学素材准备 (Teaching Materials)

**为每个知识点准备**:

#### 类比 (Analogies)
- 将抽象概念与日常经验关联
- 帮助理解原理

**示例**:
```markdown
**类比**: for循环就像工厂流水线:
- 传送带上有一箱零件(可迭代对象)
- 工人(循环体)对每个零件(元素)执行相同操作
- 处理完所有零件后,流水线停止
```

#### 对比表格 (Comparison Tables)
- 区分易混淆概念
- 强化理解

**示例**:
```markdown
| 特性 | for循环 | while循环 |
|------|---------|-----------|
| 适用场景 | 已知迭代次数 | 条件满足时继续 |
| 语法简洁性 | 简洁 | 需要手动管理计数器 |
| 常见用途 | 遍历列表、字符串 | 等待用户输入、游戏循环 |
```

#### 可视化说明 (Visual Explanations)
- 流程图、步骤图
- 内存状态变化(如适用)

**示例**:
```markdown
**执行流程可视化**:
\`\`\`
for i in [1, 2, 3]:
    print(i)

步骤1: i = 1 → 输出 1
步骤2: i = 2 → 输出 2
步骤3: i = 3 → 输出 3
步骤4: 列表遍历完毕,退出循环
\`\`\`
```

## 质量标准 (Quality Standards)

### 知识点内容质量

- **定义清晰**: 1-2句话说清楚"是什么",无歧义
- **原理适度**: 解释"如何工作",但不过度技术化
- **示例实用**: 代码示例能运行,贴近真实应用
- **陷阱准确**: 列出的常见错误确实是新手易犯的

### 苏格拉底问题质量

- **层次渐进**: 3层问题(概念→原理→应用)明确区分
- **问题开放**: 不是单纯的"是/否"问题,需要学生思考
- **检查点明确**: 每个问题有清晰的"预期回答"和"检查点"
- **覆盖完整**: 问题涵盖知识点的关键方面

### 教学素材质量

- **类比恰当**: 类比的日常经验多数人能理解
- **对比有效**: 对比表格突出关键差异,不罗列次要信息
- **可视化清晰**: 流程图/步骤图易懂,不过度复杂

## 技术实现细节 (Technical Implementation)

### 大纲解析

**工具**: Markdown解析库(如 `markdown-it`)

**关键步骤**:
1. 解析YAML frontmatter(获取元数据)
2. 提取所有`###`标题(知识点名称)
3. 读取"学习目标"、"前置知识"字段
4. 构建知识点列表

### 内容生成

**策略**:
- **定义/原理**: 基于AI训练知识生成
- **代码示例**: 优先使用常见模式,确保可运行性
- **类比**: 从教学经验库中选择合适类比

**质量控制**:
- 代码示例语法检查(Python AST解析)
- 问题难度评估(基于关键词复杂度)

### 文件生成

**工具**: AI平台的 `create_file` API

**代码示例**(概念性):
```python
file_path = f"data/chapters/{sanitize_filename(topic_name)}-prepared.md"
content = generate_prepared_markdown(knowledge_points, questions, materials)

create_file(file_path, content)
print(f"✅ 准备完成: {file_path}")
```

## 边界案例处理 (Edge Cases)

### 案例1: 抽象概念(无代码)

**场景**: 知识点是纯理论概念(如"算法复杂度"、"面向对象思想")  
**处理**:
- 代码示例改为"伪代码"或"概念图"
- 苏格拉底问题侧重概念对比和应用判断
- 类比更重要(帮助理解抽象概念)

### 案例2: 数学公式

**场景**: 知识点包含数学公式(如机器学习算法)  
**处理**:
- 使用LaTeX格式(Markdown支持)
- 提供公式的"直觉解释"(不仅是符号)
- 苏格拉底问题引导理解公式含义,而非死记硬背

### 案例3: 知识点相互依赖

**场景**: 知识点B依赖知识点A,但大纲中顺序混乱  
**处理**:
- 在知识点B的"前置知识"中标注依赖
- 在教学策略提示中说明: "需先确认学生理解[KP-A]"

### 案例4: 过于简单的知识点

**场景**: 某个知识点过于基础(如"变量赋值")  
**处理**:
- 合并到其他知识点中
- 或快速带过(减少问题数量到3个)
