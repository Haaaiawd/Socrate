# Contract: `/teacherkit.outline` Command

**Command**: `/teacherkit.outline`  
**Phase**: 1 - Learning Planning  
**Status**: Required  
**Purpose**: Generate structured learning outline with integrated teaching plan and review phase design

---

## 职责边界 (Responsibility Boundaries)

### 本命令负责 (This Command Handles)

1. **学习内容分析** (Content Analysis)
   - 读取附加文件(MD/TXT/PDF)或用户描述的主题
   - 识别主要概念、子主题、知识点层次
   - 评估内容复杂度和学习时长

2. **知识结构组织** (Knowledge Structure Organization)
   - 构建学习路径: 章节 → 主题 → 概念
   - 确定知识点之间的依赖关系(前置知识)
   - 规划知识点的逻辑顺序(由浅入深)

3. **教学计划设计** (Teaching Plan Design) ⭐ 核心增强
   - 制定教学节奏: 每个知识点的时间分配
   - 设计知识点引入顺序: 何时、为何引入某个概念
   - 规划理论与实践的穿插节奏
   - 确定检查点位置(何时检验理解程度)

4. **复习阶段设计** (Review Phase Design) ⭐ 核心增强
   - 在大纲末尾设计专门的复习阶段
   - 复习重点: **多实践实操,概念只是微微提出**
   - 规划综合练习: 结合多个知识点的实战任务
   - 设计查漏补缺机制: 识别薄弱环节并针对性加强

5. **输出文件生成** (Output File Generation)
   - 生成 `data/outlines/[name]-outline.md`
   - 使用 YAML frontmatter 记录元数据
   - 包含知识结构、教学计划、复习阶段的完整信息

### 本命令不负责 (Out of Scope)

- ❌ 详细知识点内容展开(交由 `/teacherkit.prepare`)
- ❌ 苏格拉底问题设计(交由 `/teacherkit.prepare`)
- ❌ 实操练习代码生成(交由 `/teacherkit.practice`)
- ❌ 开始教学对话(交由 `/teacherkit.lesson`)

---

## 输入约定 (Input Contract)

### 方式1: 文件附加学习 (File Attachment)

**触发**: 用户附加文件并输入 `/teacherkit.outline`

**要求**:
- 至少附加一个文件(MD/TXT/PDF)
- 文件大小 < 50MB (MVP限制)
- 文件内容可读(非损坏、非扫描PDF)

**示例**:
```
[用户附加 python-basics.pdf]
/teacherkit.outline
```

### 方式2: 主题描述学习 (Topic Description)

**触发**: 用户输入 `/teacherkit.outline "主题描述"`

**要求**:
- 提供清晰的主题描述(3-50字)
- 可选: 学习目标、时间限制、先修知识

**示例**:
```
/teacherkit.outline "Python for循环和列表推导式"
/teacherkit.outline "机器学习入门: 线性回归和逻辑回归"
```

### 输入验证 (Input Validation)

| 场景 | 验证规则 | 失败处理 |
|------|---------|---------|
| 无文件无描述 | 必须提供至少一种输入 | 提示: "请附加教材文件或描述学习主题" |
| 文件无法读取 | 检查文件格式和完整性 | 提示: "文件读取失败,请尝试转换为MD/TXT格式" |
| 主题过于宽泛 | 检测关键词模糊度 | 提问澄清: "你想学习[主题]的哪些方面?" |
| 文件过大 | 大小 < 50MB | 提示: "文件较大,建议按章节分批学习" |

## 处理流程 (Processing Flow)

### 阶段1: 内容解析 (Content Parsing)

**步骤**:
1. 读取附加文件内容或主题描述
2. 识别文档结构(标题层级、章节划分)
3. 提取关键概念和术语
4. 评估内容复杂度(初级/中级/高级)

**输出**: 内容摘要和概念列表

### 阶段2: 知识结构构建 (Structure Building)

**步骤**:
1. **章节划分** (Chapter Division)
   - 将内容分为3-7个主要章节
   - 每个章节包含2-5个主题
   - 每个主题包含1-3个核心概念

2. **依赖关系分析** (Dependency Analysis)
   - 标记前置知识要求
   - 确定学习路径(不能跳过的基础)
   - 识别可并行学习的独立主题

3. **时长估算** (Duration Estimation)
   - 理论知识点: 5-10分钟/概念
   - 实践练习: 15-30分钟/练习
   - 总学习时长估算

**输出**: 层次化知识结构树

### 阶段3: 教学计划制定 (Teaching Plan Design) ⭐

**步骤**:
1. **知识点引入策略** (Introduction Strategy)
   - 确定每个知识点的引入时机
   - 设计引入方式: 问题导入、案例导入、对比导入
   - 规划知识点之间的过渡衔接

2. **节奏控制** (Pacing Control)
   - 理论学习阶段: 2-3个概念为一组
   - 实践穿插: 每组理论后安排1个练习
   - 休息点: 每30-45分钟设置检查点

3. **渐进式深入** (Progressive Deepening)
   - 第一轮: 概念介绍(What is it?)
   - 第二轮: 原理解释(How does it work?)
   - 第三轮: 应用实践(When to use it?)

4. **教学对话指导** (Dialogue Guidance)
   - 为每个知识点预设教学目标
   - 建议苏格拉底式引导方向
   - 标记关键检查点(需确认学生理解)

**输出**: 教学计划表(时间线 + 知识点引入顺序 + 教学策略)

### 阶段4: 复习阶段设计 (Review Phase Design) ⭐

**步骤**:
1. **综合实践设计** (Integrated Practice)
   - 创建综合任务: 结合3-5个已学知识点
   - 真实场景模拟: 接近实际应用的问题
   - 难度梯度: 从简单整合到复杂应用

2. **概念快速回顾** (Quick Concept Review)
   - 一句话概念提示(不展开详细讲解)
   - 关键术语表(快速查阅)
   - 知识点关系图(可视化复习)

3. **查漏补缺机制** (Gap Identification)
   - 识别薄弱环节: 基于练习表现
   - 针对性加强练习: 为薄弱点增加额外实操
   - 可选深入: 学生可选择深入某个知识点

**复习阶段结构**:
```markdown
## 复习阶段 (Review Phase)

### 概念快速回顾 (15分钟)
- [知识点1]: 一句话总结
- [知识点2]: 一句话总结
- [关键术语表]

### 综合实践1: [任务名称] (30分钟)
- 涉及知识点: [KP1, KP2, KP3]
- 任务描述: [真实场景问题]
- 提示: [引导性问题]

### 综合实践2: [进阶任务] (45分钟)
- 涉及知识点: [KP1-KP5]
- 挑战要求: [更复杂的整合应用]
```

**输出**: 复习阶段计划(实践为主 + 概念速览)

### 阶段5: 输出文件生成 (File Generation)

**步骤**:
1. 使用AI平台的 `create_file` 工具
2. 生成 `data/outlines/[sanitized-name]-outline.md`
3. 写入YAML frontmatter + Markdown内容

**输出**: 完整大纲文件

## 质量标准 (Quality Standards)

### 大纲结构质量

- **深度适中**: 3-4层层级(章节 → 主题 → 概念 → 要点)
- **广度合理**: 每章2-5个主题,避免过度拆分
- **时长合理**: 单个知识点5-15分钟,避免过长或过短
- **依赖清晰**: 前置知识明确标注,学习路径无循环依赖

### 教学计划质量

- **节奏合理**: 理论与实践穿插,避免长时间纯理论
- **引入自然**: 每个知识点有明确的引入策略
- **检查点恰当**: 关键概念后设置检查点
- **时间分配**: 符合认知规律(简单概念短,复杂概念长)

### 复习阶段质量

- **实践为主**: 综合练习占比 > 70%
- **概念精简**: 概念回顾仅提供一句话总结和术语表
- **综合性强**: 练习需结合多个知识点
- **真实场景**: 任务接近实际应用,非纯理论题

**指标**:
- 术语密度(专业术语数量/总字数)
- 概念抽象度(基于关键词匹配)
- 前置知识要求(基于内容分析)

**输出**: 初级/中级/高级

## 与其他命令的协作 (Command Integration)

### 输出 → `/teacherkit.prepare` 的输入

**传递内容**:
- 知识点列表(ID、名称、层级)

**传递内容**:

**lesson 依赖的字段**:
- 当前应该教授的知识点

- 何时触发复习阶段

## 边界案例处理 (Edge Cases)

### 案例1: 超大文件

**场景**: 附加500页的完整教材  
**处理**:
1. 警告用户: "文件较大,建议分章节学习"
2. 提供选项: A)选择章节 B)生成完整大纲(耗时)
3. 如果用户坚持完整大纲,生成摘要式大纲(减少细节)

### 案例2: 无结构文本

**场景**: 附加一份没有标题层级的纯文本笔记  
**处理**:
1. AI主动分析内容语义
2. 基于段落主题自动划分章节
3. 在输出中说明: "已基于内容语义自动划分结构"

### 案例3: 多文件冲突

**场景**: 附加2个文件,内容有部分重叠  
**处理**:
1. 检测重复内容
2. 提示用户: "检测到重复内容,已自动合并"
3. 生成统一大纲,标注内容来源

### 案例4: 非编程主题

**场景**: 用户请求学习"历史/文学"等非编程主题  
**处理**:
1. 仍然生成大纲(系统不限于编程)
2. 教学计划调整: 理论为主,实践为思考题/讨论题
3. 复习阶段: 案例分析/综合论述题
